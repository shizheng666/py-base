# 模块 4：面向对象、协议与 Pythonic 设计

## 学习目标

- 理解类、实例、继承、组合、property、魔术方法
- 理解为什么 Python 常优先用组合与协议，而不是层层继承
- 学会把前端熟悉的 service/model 思维迁移过来

## 核心概念

- `class` 是组织状态和行为的工具，不是唯一设计手段
- 鸭子类型强调“对象会不会做这件事”，而不只看继承链
- `property` 让读取属性和调用方法之间的体验更平滑

## 代码讲解重点

- 什么时候适合用 dataclass，什么时候适合用完整类
- 为什么“实体模型”和“服务对象”最好分层
- 为什么不要为了“像 Java”而创建过多抽象基类

## 与前端对照

- 类似前端里的 model、store、service 分工
- 更强调行为边界，而不是过度装饰器化或元编程

## 常用库

- `dataclasses`
- `typing.Protocol`
- `abc`

## 实战任务

- 为主项目设计 `TaskService`
- 把“数据对象”和“业务规则”拆开
- 对比继承方案和组合方案
