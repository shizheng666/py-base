# 教程编写与代码讲解规范

这套教程统一采用 skills 中强调的工程规范来组织内容。

## 1. 代码设计原则

- 先定义目标，再写代码
- 示例遵循 `YAGNI`，只实现当前问题需要的最小能力
- 文件职责清晰，一个文件尽量只解释一个核心概念
- 优先展示 Pythonic 写法，而不是把 JavaScript 思路原样翻译过来

## 2. 代码讲解模板

每段代码统一按下面顺序讲解：

1. 这段代码解决什么问题
2. 输入和输出分别是什么
3. 核心逻辑如何工作
4. 如果用前端思维该怎么理解
5. Python 里更 idiomatic 的写法是什么
6. 为什么不是另一种写法
7. 最容易踩的坑是什么

## 3. 示例组织原则

- 每个重要知识点都提供：
  - `正确写法`
  - `错误写法`
  - `JavaScript/TypeScript 对照`
- 从小函数开始，再过渡到模块、服务、接口和项目结构
- 所有例子尽量配测试，而不是只给输出截图

## 4. 练习与验证原则

教程显式引入两条来自 skills 的工作纪律：

- `test-driven-development`：在主项目和关键练习里优先用测试定义行为
- `verification-before-completion`：每章最后都要用命令验证，而不是口头宣布“完成”

每章验证至少包含以下一项：

- 运行 `pytest`
- 启动 FastAPI 应用并调用接口
- 运行脚本并检查输出
- 验证格式化、类型检查或迁移命令

## 5. 与前端经验的对照方式

教程默认你熟悉：

- React/Vue 等组件化思想
- TypeScript 类型标注
- Promise/async/await
- Node.js 项目结构
- REST API 联调

因此每章都会回答两个问题：

- 这个概念在前端里对应什么
- Python 为什么经常不按前端的直觉来写
